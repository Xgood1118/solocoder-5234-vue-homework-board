我们机构想给中学生做一个在线作业看版,老师和学生登录后看到的首页就是一个 Kanban 看板,5 列布局,作业卡片在不同列之间流转。技术栈 Vue 3 加 Vite,数据存浏览器本地(作业有图片附件,localStorage 容量不够,改用浏览器内置的 Indexed 存储方案),启动后是个本地单页应用,校园内网用就行。

看板的 5 列从左到右依次是: 待办(老师布置了但学生还没开始做的)、进行中(学生点开了但还没提交的)、已提交(学生交了但老师还没批)、已批改(老师批完了,学生还没订正)、已订正(学生订正完提交了,这一轮作业结束)。作业卡上要能看到: 科目、题号简述、布置时间、截止时间、提交时间(如果在已提交/已批改/已订正三列里)、当前分数(如果在已批改/已订正两列里)、老师评语(已批改之后显示)。卡片颜色按科目区分(语数外理化生用不同色),方便一眼扫过去看出哪门课的事最多。

身份切换和权限: 系统支持老师和学生两种身份登录。老师的看板是"班级维度"的,看的是全班所有学生所有作业的状态,按学生姓名再分组(同一个学生连续 5 张卡聚在一起,方便老师追这个学生的进度);学生的看板是"个人维度"的,只看自己的作业。老师可以拖动卡片在不同列之间流转(比如把一张"待办"卡直接拖到"已批改"并打 0 分,表示"这个学生没交直接给 0 分"),但学生只能把自己的"已批改"卡片往"已订正"列拖(意味着订正完成),不能往其他列拖。两种身份的看板视觉上要明显区分(顶部有个角色徽章 + 配色不同)。

状态机要明确: 一份作业的生命周期是 布置→待办→(学生点击开始)→进行中→(学生提交)→已提交→(老师批改)→已批改→(学生订正)→已订正。每个转移都有合法操作方(谁可以触发),非法转移要拒绝并提示。特殊转移: 待办→已批改(老师强制判 0 分,跳过中间); 进行中→已批改(学生交白卷,老师给 0 分); 已批改→已批改(老师重新批改,分数会覆盖前一次)。已订正状态的作业不能再回到已批改,除非老师手动"打回重做"。

订正流程: 已批改的作业如果分数低于某个阈值(比如 60 分),系统自动给该学生生成一张"订正卡"显示在已批改列,提示"建议订正"。学生订正完后提交,作业进入"已订正"列,但订正后的分数系统不自动覆盖原分数,而是额外记录"订正得分"和"订正用时",老师最终可以决定"原分数 + 订正分数取平均"或者"以原分数为准"。

筛选和排序: 老师端能按科目筛选(只看数学的作业)、按学生筛选(只看某个学生的作业)、按截止时间排序(快到期的置顶)。学生端能按状态筛选(只看"已批改"的需要订正)、按科目筛选。搜索框支持按题号/老师评语关键字搜索卡片。

历史回看: 每一份作业卡片可以点开看"流转历史",显示这张卡从布置到现在经过的每一次状态变化(谁、什么时间、做了什么操作、当时的备注)。历史按时间倒序,方便回溯"这张卡为什么从已批改又被改回已批改"。

涉及模块: 看板视图模块(5 列布局、卡片渲染、拖拽支持)、状态机模块(转移规则校验、事件触发)、身份权限模块(老师/学生视图切换、操作权限校验)、作业数据模块(浏览器 Indexed 存储、CRUD)、订正流程模块(订正卡生成、订正分数管理)、流转历史模块(事件日志记录、回看查询)。

几个边界: 同一份作业在多个老师之间流转(比如数学老师请病假,代课老师接手),已批改的分数归属要明确为最后批改的那位老师(不要叠加);作业卡上的图片附件(学生拍照)要能正常显示,用 FileReader 读成 base64 存浏览器 Indexed 存储;老师给 0 分时系统不自动转"已订正",需要老师手动标记"需要订正"才会出现订正卡;作业被老师删除时(误布置的),状态机要能识别这种"软删除",已提交和已批改的作业不能被物理删除只能软删;卡片拖拽时如果目标列不接受该状态(比如学生把"待办"卡往"已订正"拖),要直接弹回原位并提示原因。
